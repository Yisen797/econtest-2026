# ESP32-S3 N16R8 开发者完整参考

## 快速开始（新对话直接照做）
```bash
export PATH="$HOME/.platformio/penv/Scripts:$PATH"

# 烧录 S3接收端 (AP+UDP)
cd "<项目根目录>/S3接收端"
pio run -t upload          # COM口变了改 platformio.ini 的 upload_port

# 烧录 S3发送端 (采集+UDP)
cd "<项目根目录>/S3发送端"
pio run -t upload --upload-port COM6

# OpenMV 端: 在 OpenMV IDE 中打开此文件运行
# <项目根目录>/OpenMV端/OpenMV端视频发送.py
```

## 硬件

### 开发板
- 芯片: ESP32-S3-WROOM-1 (N16R8 = 16MB Flash + 8MB OPI PSRAM)
- 原理图: ESP32-S3-SCH-V1.4 (PCB: ESP32-S3-COREBOARD V1.4)
- USB转串口: **CH343P** (VID:1A86 PID:55D3), 自动烧录(DTR→EN, RTS→IO0)
- 两个Type-C: **USB1**→CH343P→UART0 (烧录用), **USB2**→GPIO19/20 (内部USB OTG, JTAG)
- 板载: NeoPixel WS2812(GPIO48), BOOT键(GPIO0), PWR_LED(红, 不可控)

### J1 排针 (左侧 22脚)
```
1:3.3V  2:3.3V  3:EN  4:GPIO4  5:GPIO5  6:GPIO6  7:GPIO7
8:GPIO15  9:GPIO16  10:GPIO17  11:GPIO18  12:GPIO8
13:GPIO3  14:GPIO46  15:GPIO9  16:GPIO10  17:GPIO11
18:GPIO12  19:GPIO13  20:GPIO14  21:5V  22:GND
```

### J2 排针 (右侧 22脚)
```
1:GND  2:U0TXD  3:U0RXD  4:GPIO1  5:GPIO2  6:GPIO42
7:GPIO41  8:GPIO40  9:GPIO39  10:GPIO38  11:GPIO37  12:GPIO36
13:GPIO35  14:GPIO0(BOOT)  15:GPIO45  16:GPIO48(Neo)
17:GPIO47  18:GPIO21  19:GPIO20(USB_D+)  20:GPIO19(USB_D-)
21:GND  22:GND
```

### 不可用引脚
GPIO26-37: OPI Flash/PSRAM 占用

### 扩展板
| GPIO | 位置 | 功能 |
|------|------|------|
| 14 | J1-20 | 蜂鸣器 (低电平响, HIGH=灭) |
| 2  | J2-5  | 开关1 (按下=LOW, 上拉) |
| 38 | J2-10 | 开关2 |
| 47 | J2-17 | 开关3 |
| 21 | J2-18 | 开关4 ⚠️与MPU6050 SDA冲突, 二选一 |
| 9  | J1-15 | OLED SDA |
| 10 | J1-16 | OLED SCL |

## 可选功能库（已实现，可随时启用/组合）

### Web 网页显示
- 用法: S3接收端内置, WiFiServer+WebServer, 端口80
- 端点: `/`(HTML页) `/data`(JSON) `/stream`(MJPEG视频流)
- 依赖: `<WebServer.h>`, `<WiFi.h>` (均为ESP32核心库)

### OLED 显示 (SSD1306 128x64 I2C)
- 接线: SDA=GPIO9, SCL=GPIO10, 地址0x3C
- 依赖: `adafruit/Adafruit SSD1306 @ ^2.5.7`
- ⚠️ **OLED不支持中文**, 只显示ASCII/数字
- ⚠️ `oled.printf("%f")` 可能崩溃, 用 `oled.print()` 替代
- 参考: 立创天猛星MSPM0G3507项目的MPU6050显示格式

### MPU6050 六轴传感器
- 接线(发送端): SDA=GPIO21, SCL=GPIO22
- 数据: 加速度(m/s²)+角速度(°/s)+温度(°C)→计算Pitch/Roll
- 依赖: `adafruit/Adafruit MPU6050 @ ^2.2.0`
- ⚠️ 发送端GPIO21与扩展板开关4冲突

### OpenMV 视频推流
- 接线: OpenMV P4(TX)→S3 GPIO16(RX), GND共地
- OpenMV端: `OpenMV端视频发送.py`, QVGA 320x240, JPEG quality45, 460800baud
- ⚠️ 只能用软件JPEG (RGB565+compress), 硬件JPEG模式(sensor.JPEG)会在OpenMV v4.8.1上触发DMA缓存冲突硬复位

### 蜂鸣器
- 接线: GPIO14
- 低电平响: `digitalWrite(14, LOW); delay(200); digitalWrite(14, HIGH);`

### 开关按键
- 四个开关: GPIO2/38/47/21
- 输入上拉, 按下为LOW
- 消抖: 记录上一状态, 检测下降沿 (HIGH→LOW)

## 协议

### UDP 传感器 (:8888)
52字节 SensorPacket:
```c
#pragma pack(1)
struct { float p,r,ax,ay,az,gx,gy,gz,t; float mspm0[4]; uint32_t seq; };
```

### UDP 视频 (:8890)
分片重组, 每片≤1400字节:
```
[2B frame_id LE][1B frag_idx][1B total_cnt][payload]
S3接收端按frame_id收集, frag_idx排序, 全部到齐后组装
```

### JPEG 自同步
发送端直接推JPEG流, 接收端通过SOI(FFD8)/EOI(FFD9)自动检测帧边界, 无需同步头。

## 踩坑记录

### 1. S3纯AP模式ESP-NOW不收包 ❌
官方ESPNow_Basic_Slave例程验证: S3在纯AP模式下ESP-NOW接收不工作。
AP+STA双模也无效。如需ESP-NOW, 输入角色: S3作为发送端(STA模式)。

### 2. TCP在标准ESP32上不稳定 ❌
标准ESP32(非S3)用TCP时WiFi启动触发欠压复位。降频+降功率可短暂连通但不稳定。
**解决方案: 换UDP**, 已验证稳定运行。TCP代码保留在 `ESP32无线传输TCP方案（未成功）/`。

### 3. AsyncUDP::listen() 必须在WiFi初始化之后 ✅
先 `WiFi.mode(WIFI_AP)` + `WiFi.softAP()`, 再 `udp.listen()`。
否则崩溃无输出。

### 4. OLED的printf("%f")会崩溃 ✅
用 `oled.print(value, decimals)` 替代 `oled.printf("%.1f", value)`。

### 5. SSD1306不支持中文 ✅
OLED只显示英文/数字。网页HTML可以用中文(浏览器渲染)。

### 6. WiFiClient.connected() 在对方重启后仍返回true ✅
导致TCP旧连接残留, 新连接无法被接受。
**解决方案: 加超时检测** (X秒无数据→强制disconnect+accept新连接),
或直接换UDP从根源消除此问题。

### 7. S3 COM端口漂移 ✅
CH343P在不同USB口/重启后COM号可能变化。
`platformio.ini` 的 `upload_port` 和 `monitor_port` 需要同步更新。
用 `powershell -Command "[System.IO.Ports.SerialPort]::GetPortNames()"` 查当前COM口。

### 8. PlatformIO内置OpenOCD不兼容极客ST-Link克隆版 ✅
F4项目的ST-Link只能用ST-LINK_CLI.exe (GUI或命令行, Connect Under Reset模式)。

### 9. 标准ESP32 WiFi连接时需降频 ✅
`setCpuFrequencyMhz(80)` → WiFi.begin() → 连上后恢复240MHz。
`WiFi.setTxPower(WIFI_POWER_8_5dBm)` 降低发射功率减少电流尖峰。

### 10. WiFi密码/SSID全局替换 ✅
涉及4个WIFI_SSID/WIFI_PASS位置: 发送端main.cpp + 接收端main.cpp。
用 `sed -i 's/旧名/新名/g'` 批量替换。

## 常用命令
```bash
# 查COM口
powershell -Command "[System.IO.Ports.SerialPort]::GetPortNames()"

# 查CH343设备
powershell -Command "Get-PnpDevice | Where-Object { $_.FriendlyName -like '*CH343*' }"

# 编译检查(不烧录)
pio run

# 清理重建
pio run -t clean && pio run -t upload

# 看串口
pio device monitor -b 115200 --port COM14
```
